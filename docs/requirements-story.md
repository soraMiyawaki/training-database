# 要件ストーリー（仮）：定食屋「みやこ食堂」売上管理DB

- 位置づけ：研修生に渡す「顧客からの依頼」の仮案。研修生はこれを読んで要件整理（W1）を行う
- 状態：**仮作成**。店名・数値・期間はすべて架空。講師レビュー後に確定する
- 対応する1次データ：`docs/data-flow.md` の 2 章

---

## 1. 背景

「みやこ食堂」は駅前の小さな定食屋（1店舗、テーブル8卓・カウンター6席、営業 11:00〜15:00 / 17:00〜21:00、定休日：日曜）。

店主は売上をレジ（POS）の日次 CSV と、自分で管理しているメニュー表の Excel で把握しているが、月末に CSV を手で貼り合わせて集計しており、毎月半日かかっている。数字が合わないこともある。

2026年9月1日にメニューの値上げを行った。値上げ後に売上が増えたのか、客が減っただけなのかを知りたいが、今の方法では比較できない。

## 2. 登場人物

| 人物 | 立場 | 研修での役割 |
|---|---|---|
| 店主（宮古さん） | 依頼者。売上を見たい | 講師が演じる。研修生のヒアリングに答える |
| ホールスタッフ 4 名 | 注文を受けてレジに入力する | データ上の「担当者」 |
| 研修生 | DB を設計・構築するシステム担当 | 本人 |

## 3. 現在の業務の流れ

1. 客が着席し、ホールスタッフが注文を聞いてレジに入力する（1回の来店 = 1伝票）
2. 追加注文は同じ伝票に追加される
3. 入力ミスはレジで「取消」する。取消は削除ではなく、取消行として CSV に残る
4. 会計は伝票単位。支払方法は 現金 / クレジットカード / QRコード決済
5. 閉店後、レジから当日分の CSV を出力し、店主の PC に保存する
6. メニューの追加・値上げ・販売終了は、店主が Excel のメニュー表を更新し、レジ側の商品登録も手で直す（**両者が一致している保証はない**）

## 4. 店主の要望（研修生がヒアリングで引き出すべき要件）

| ID | 要望（店主の言葉） | 研修上の論点 |
|---|---|---|
| R-01 | 日ごとの売上を見たい | 取消行の除外、営業日と日付の扱い |
| R-02 | メニューごとに何がどれだけ売れたか知りたい | 注文と明細の分離、GROUP BY |
| R-03 | 9月の値上げ前後で、売上と客数を比べたい | **注文時単価の保持**（メニューの現在価格で計算すると過去の売上が変わってしまう） |
| R-04 | 昼と夜で、どちらが稼いでいるか知りたい | 日時からの時間帯区分 |
| R-05 | 支払方法の割合を知りたい（キャッシュレスの手数料を検討するため） | 会計テーブル |
| R-06 | スタッフごとの担当件数を知りたい | 従業員マスタ、担当者が空欄の伝票の扱い |
| R-07 | 来月から、レジの CSV を毎日そのまま取り込めるようにしたい | 取込手順の再現性（同じファイルを2回取り込んでも二重計上しない） |

## 5. 対象外（店主に聞かれたら「今回はやらない」と答える）

- 食材の在庫・仕入（Level 2 の多店舗化テーマで扱う）
- 予約、顧客（会員）管理、ポイント
- 画面の作成（SSMS で SQL を実行して結果を見られればよい）
- テイクアウト（Level 2 の発展要素）

## 6. 店主から渡されるもの

- レジ売上 CSV：2026/08/01〜2026/09/30 の 2 か月分（値上げ前後の比較用。日曜定休、8/13〜8/15 はお盆の臨時休業でファイルなし）
- メニュー表 Excel
- スタッフ名簿 Excel
- 席の一覧（手書きのメモを店主がテキストにしたもの）

店主のひとこと：「レジの CSV はたまに変なのが混ざってる気がするけど、よくわからない」
→ データ品質の問題を研修生自身に見つけさせるための伏線（内容は `docs/data-flow.md` 4 章。**研修生には見せない**）

## 講師向け：このストーリーで決めていること・決めていないこと

| 項目 | 決めた理由 / 未決事項 |
|---|---|
| 期間を 2026/08〜09 の 2 か月にした | R-03（値上げ前後比較）を成立させるため。研修開始（11月）時点で締まっている期間にした |
| 値上げを 9/1 にした | 注文時単価を持たせる必然性を作るため。提案書 6 枚目の学習ポイントと一致 |
| 取消を「取消行」で表現 | 売上集計で除外条件を考えさせるため |
| 天気 | ストーリー・要件には含めない。データ生成時に「雨の日は来客が減る」隠れた要因としてのみ使う（架空の値）。研修生に聞かれた場合、店主は「雨の日は暇な気がする」程度に答える |
| 1 日あたりの伝票数 | 生成スクリプトの仮定値（`data/answer/README.md`）。2 か月で約 3,300 伝票・明細 約 10,500 行。実在の飲食店データに基づく数値ではない |
| 店主役のヒアリング想定問答 | 未作成。ストーリー確定後に作る |
